# Factor Factory｜LLM 驱动的量化因子研发流水线

> 将“研究命题 → 因子代码 → 本地计算 → 远程评估 → 质量筛选 → 迭代优化 → 因子入库”组织成可重复运行的工程闭环。

本仓库是量化因子工厂的公开展示版本，重点呈现系统架构、核心模块与工程方法。行情/财务数据、远程评估平台、内部实验结果和业务配置不在仓库中，因此它适合代码审阅与技术讨论，不应被视为可直接复现实盘表现的交易策略。

## 30 秒了解项目

| 问题 | 回答 |
| --- | --- |
| 解决什么问题？ | 降低人工编写、排错和筛选因子的重复成本，让大模型生成的研究想法进入可执行、可评估、可追踪的流程。 |
| 我做了什么？ | 设计并开发双生产线架构、Prompt/Agent 工作流、本地计算、远程任务衔接、公式去重、Judge 筛选、进化优化和注册表存储。 |
| 覆盖哪些因子？ | 量价与基本面两类因子，共用工程基础设施，同时保留各自的数据频率和算子语义。 |
| 如何控制生成质量？ | 通过受控算子库、代码纠错、本地执行、远程评估、公式 Hash 去重和多角色评审形成多层校验。 |
| 公开仓库能证明什么？ | 可以审阅系统拆分、代码组织、Agent 协作、研究资产管理和可扩展性；内部数据与研究结论未公开。 |

## 核心设计

### 1. 双生产线架构

- 量价工厂：围绕 OHLCV 矩阵、时序/截面算子和不同研究风格生成候选因子。
- 基本面工厂：按季频快照组织财务数据，保留 TTM、同比、环比等财务算子的时间语义。
- 公共基础设施：统一配置、任务提交与轮询、结果清洗、历史记忆、公式去重和注册表存储。

### 2. 多阶段生成与纠错

- 将研究命题拆成逻辑设计、代码生成和执行纠错阶段。
- 向模型注入受控算子库和字段约束，降低不可执行表达式比例。
- 对公式做规范化与 Hash 去重，并将历史结果回填下一轮 Prompt，减少重复生成。

### 3. 质量筛选与进化优化

- 本地计算先检查代码可执行性和因子实体，再提交远程平台评估。
- Judge 将评估指标、因子逻辑和生成记录组合成结构化上下文。
- 对潜力因子执行 Doctor → Coder → Referee 迭代，并记录 KEEP / EVOLVE / PIVOT / TERMINATE 状态。

### 4. 研究资产沉淀

- 主注册表保存成功生成的因子，精品注册表保存通过筛选的因子。
- 同步保存公式、代码、标签、评审意见和进化历史，便于复盘与二次研究。
- 量价与基本面生产线复用同一套存储语义，减少重复工程。

## 运行说明

项目需要 Python 环境、兼容 OpenAI 接口的 LLM 服务、符合字段约定的行情/财务数据以及远程评估接口。配置示例见 [`.env.example`](.env.example)。

~~~bash
cp .env.example .env
python -m factor_engine.pv_main
# 或
python -m factor_engine.fund_main
~~~

请勿提交真实密钥、内部服务器地址、专有数据或未获授权的研究结果。
